# ОСВЕД — публикация защищённого кабинета

Веб API и Telegram бот используют **один backend и одну SQLite**. Docker-порт
публикуется исключительно на `127.0.0.1:18765`; вовне должен смотреть только nginx с HTTPS.

## Один раз на Hermes

1. В DNS для `osved.tima.biz` должен быть A → `31.76.77.87` (актуальный Hermes для staging).
2. Должны быть установлены nginx и Certbot с nginx-плагином; порты 80/443 доступны для HTTP-01 и HTTPS.
3. Убедиться, что последний GitHub staging deploy прошёл и внутренний веб backend поднялся: `curl -fsS http://127.0.0.1:18765/healthz`.
4. Выполнить под `timas`: `sudo bash /opt/osved/staging-source/deploy/activate-osved-web.sh`.

Скрипт откажется менять nginx, если домен не направлен на Hermes,
порт приложения не отвечает либо целевой vhost уже существует.
Никакие секреты не печатаются; существующие vhost и сертификаты не перезаписываются.
Certbot может запросить подтверждение для ранее не настроенной учётной записи.
После успешного HTTPS-ответа скрипт добавляет `OSVED_WEB_URL=https://osved.tima.biz`
в приватный `.env` и перезапускает ОСВЕД. Только после этого
кнопка «Веб-кабинет» в Telegram начинает открывать WebApp.

## Проверка

- `curl -fsS https://osved.tima.biz/healthz` → `{"status":"alive"}`
- Анонимный `/api/overview` должен отвечать 401 (данные не доступны публично)
- Через кнопку веб-кабинета в приватном чате Telegram: сервер проверяет
  подпись `initData`, owner ID, срок действия, затем выдаёт сессию
- Сохранение новостей и переключение источников отражаются в общей SQLite
- На компьютере без Telegram Mini App вход пока закрыт: это **не** публичный
  логин-виджет и не выданная всем ссылка

## Ограничения

Готовность сайта не означает наличие проверенных новостей.
До настройки реального AI-провайдера и тестового выпуска конвейер
показывает только непроверенные события радара, отдельным разделом.
Не включать платное расписание вслепую и не снимать редакционные quality gates.
