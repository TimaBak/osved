# ОСВЕД — Source First: стратегия наполнения и экспорт материалов

Дата: 2026-10-23. Принятое изменение последовательности: прежде чем расширять AI-аналитику, обеспечить уверенный импорт и сбор множества источников. Это дорожная карта, не заявление о полной поддержке всех площадок.

## Цель первой зрелой версии
Владелец добавляет 100+ источников по ссылке или собственному списку подписок, распределяет по темам и видит сырой поток публикаций, дату проверки, причины пропусков, статус подключения, дубли и ошибки. Система хранит реальные исходные материалы, не генерирует недостоверные новости из пустой базы. Отдельно включаем AI-сортировку и редакционный выпуск, когда объём и качество данных проверены.

## Порядок по продуктовым блокам
- **S1 — Центр источников и массовое наполнение (текущий приоритет).** Реестр с гибкими темами, добавить по ссылке, пакетный импорт, импорт личных подписок по официальному OAuth, проверки подключения, пауза и редактирование, реальная свежесть и ошибки. Расширять платформы по отдельности с доказанным реальным fetch. 150 публичных GitHub/Reddit — размер каталога, НЕ гарантия, что все 150 будут опрошены за один цикл.
- **S2 — Универсальный входящий поток.** Сохранять все разрешённые записи с платформенным ID, URL, временем публикации и сбора, первичным языком, типом содержимого; различать «получено» и «отфильтровано», не скрывать неуспешный запрос.
- **S3 — Темы и навигация на сырых данных.** Платформа, рубрика, пользовательская тема, автор, компания, продукт, теги; ручные темы сначала, AI-предложения только с объяснением и без перезаписи пользовательских рубрик.
- **S4 — События и интеллект.** Кластеризовать повторные сообщения, оценивать новизну и интерес, проверять независимые источники; только затем AI-редактор по структурному JSON и выпуск проверенных статей.
- **S5 — Доставка и внешние каналы.** Персональная лента/Telegram, расписания, контроль стоимости, блог на другом сайте через собственный защищённый publishing API.

## Платформенная матрица подключения

| Источник | Способ получения | Первая реализация | Проверка и ограничения |
|---|---|---|---|
| Telegram публичные каналы | существующие MTProto/Monid адаптеры, по реально доступным credentials | идентификатор канала, дата, поступившие посты | проверить доступ к конкретному каналу, включая «Не баг, а фича»; никакой имитации подписки |
| YouTube каналы | канал ID + Atom (метаданные); личные подписки отдельно OAuth | URL, новые видео, автор, дата | @handle через разрешённый resolver; субтитры отдельно, без выдуманных транскриптов |
| GitHub | публичные repo/releases, read-only account import | owner/repo, last fetch | лимиты GitHub API, pagination, release vs commit |
| Reddit | публичные сообщества + разрешённый доступ | r/community и последние сообщения | API и rate limits, без обходов |
| RSS/Atom, личные блоги, Habr, vc.ru, Tproger, OpenNET, HN, DEV | allowlisted RSS или официальные API | безопасная URL-подписка + журнал | SSRF/DNS/rebinding, редиректы, лицензионное хранение, robots/ToS |
| X, другие соцсети | официально доступный API либо разрешённый адаптер | автор/профиль и посты, где это возможно | ключи/квоты/условия, не притворяться готовой интеграцией |
| arXiv, научные базы | официальный feed/API | тема/запрос и новые публикации | атрибуция и ограничения объёма |
| Собственный сайт, API, webhook | проверенный RSS/API и авторизованная интеграция | единый протокол source items | вход только через auth, лимиты, аудит, idempotency |

## Импорт
- Один диалог «Добавить источник»: распознать платформу, проверить URL и доступность, явно указать, какие виды контента собираются.
- Пакеты CSV `platform,url,category,topics`, TXT по строкам; предпросмотр перед подтверждением, дедуп по canonical ID, ошибки по строкам, пачки до 25.
- Импорт подписок OAuth отдельно от публичных ссылок. Нет автовключения всех источников после OAuth без подтверждения.
- Темы множественные и независимы от платформы; категория каталога источника не является фактом о каждой публикации.
- Лимиты количества источников не должны автоматически означать повышение частоты/расходов коллектора. Интервал, concurrency, квоты, retries и бюджет исследовательских операций — отдельные ограничители.

## Безопасный API публикации для блога (проект, не реализовано)
- `GET /api/v1/publications` — пагинированный список **только явно опубликованных** материалов (фильтры topic, published_after, cursor).
- `GET /api/v1/publications/{id}` — title, slug, summary, semantic sections, timestamps, source URLs, canonical URL, attribution, language, revision, editorial status.
- Владелец создаёт publishing token с scopes `publications:read`; сначала owner-only, затем отдельно включаем публичные публикации с запретом утечки приватной ленты и заметок.
- Изображения и права на воспроизведение — явно лицензированы; HTTP cache/ETag, rate limits, idempotent IDs, webhooks только с HMAC и retry log.
- Сайт-получатель решает как рендерить материалы, ОСВЕД остаётся источником фактов/статуса публикации.
- По умолчанию внешнему сайту не отдавать пользовательские подписки, личные заметки, сырой закрытый контент и неутверждённые AI-тексты.

## Условия приёмки перед масштабным AI
1. Реально зарегистрировать и проверить каналы из Telegram, YouTube, GitHub, Reddit и хотя бы один безопасный RSS; всё, что недоступно, показать явно.
2. Проверить в SQLite реальные item IDs по нескольким контрольным источникам, не ограничиваться «источник успешно добавлен».
3. Три контролируемых сбора на растущем каталоге, без потерь, тайных списаний, без бесконечного retry и без критической деградации Hermes.
4. Темы/категории в UI и API; пользователь видит сырую ленту сигналов независимо от производства редакционных карточек.
5. После подтверждения S1–S3 вернуться к интеллекту, редакции и внешнему publishing API по отдельным PR.

## Текущая конкретная поставка
Расширен лимит **только** для вручную добавляемых публичных GitHub/Reddit источников до 150, без автоматической активации дорогих запросов. Это устраняет прежний продуктовый барьер на 50, но само по себе не включает RSS/Telegram/X/YouTube или регулярный автоматический сбор. Остальные платформы требуют своих доказанных путей регистрации и тестов.
