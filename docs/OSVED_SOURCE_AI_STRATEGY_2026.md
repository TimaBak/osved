# ОСВЕД — источники, перевод, YouTube и экономная AI-архитектура

**Дата:** 22.10.2026. **Статус:** стратегический план + реализуемый безопасный первый этап.
Основание: `docs/OSVED_PRODUCT_VISION.md`, `docs/OSVED_INTERESTS_AND_ACCOUNT_SOURCES.md`, актуальный код `main`.
Эта дорожная карта не объявляет ещё не включённые OAuth и AI-провайдеры рабочими.

## Северная звезда

ОСВЕД — **русскоязычная персональная система знаний**. Важнее не 1 000 источников,
а единое объяснимое событие, связанное с человеком/компанией/темой, с достоверными
первоисточниками, кратким русским обзором и персональной релевантностью.
Отдельные контуры: `сырой сигнал` → `проверенный материал` → `моё исследование`.
Рекомендатель не имеет права повышать статус достоверности материала.

## Что уже существует

- Есть сборщики для Telegram, X, Reddit, RSS, GitHub, YouTube и других платформ;
  доступность отдельных платных и авторизованных адаптеров зависит от ключей,
  разрешений, лимитов и реальных запусков на Hermes.
- Есть редакционный pipeline, общий SQLite, один владелец, веб/Telegram,
  избранное, заметки, обратная связь по публикациям и ручные приоритеты тем.
- **Пока нет доказанного выпуска новой проверенной карточки на боевом сервере**
  после подключения внешнего AI-провайдера. Не путать сбор сигналов с готовыми новостями.
- Новые YouTube-выжимки в текущем коде требуют AI API, транспорта субтитров
  и явно включённого бюджета. Исторически `openrouter_api_key` не настроен
  и `video_report_budget_enabled=false`; не менять бюджет автоматически.
- Есть локальный SVG-конструктор обложек, но пока нет работающей генерации
  изображений нейросетью и полноценного перевода статей.
- В текущей итерации добавляются **категории существующих источников**
  и **проверяемая диагностика AI-функций**. Это ещё не OAuth-подписки.

## Информационная архитектура источников

```
Мои источники
├─ Мессенджеры: Telegram (каналы, публикации)
├─ Социальные сети: X / Weibo (авторы, списки)
├─ Сообщества: Reddit / V2EX / Zhihu (разделы, дискуссии)
├─ Видео: YouTube (каналы, ролики, субтитры)
├─ Разработка: GitHub (репозитории, stars, releases)
├─ Сайты: RSS/Atom, блоги, СМИ, компании
└─ Научные публикации (расширение): arXiv, Crossref, OpenAlex
```

Каждый источник: `платформа → аккаунт/автор/канал → тема → частота → статус →
последний сбор → квота → стоимость → ошибки`. Темы и интересы — отдельная
ось; один канал может быть полезен сразу по нескольким темам.
Публичные источники отделять от **моих личных подписок**, а `подключённый`
не значит `собрал и проверил`. Показывать импортированный источник и
источник, автоматически предлагаемый ОСВЕД, раздельно.

### Импорт аккаунтов: не копирование сессий

1. **Публичные источники**: без аккаунтов; стандартные API/RSS с соблюдением ToS.
2. **OAuth с согласия пользователя**: ограниченный read-only scope, отдельное
   зашифрованное хранилище токенов, refresh/revoke/delete, статусы, аудит,
   CSRF/OAuth state, запрет скрытого импорта.
3. **Загрузка экспорта подписок**: собственный файл пользователя; предпросмотр
   платформы, каналов и тем перед импортом; импорт не запускает авторассылку.
4. Telegram user-auth — только через отдельную официально разрешённую схему и
   безопасное хранилище. Нельзя просить прислать Telegram session-string,
   cookies сайта или пароль в чат/репозиторий.

**Проверенные особенности на октябрь 2026:**
- YouTube `subscriptions.list?mine=true` требует OAuth; расход квоты 1 unit
  за вызов списка; обязательна постраничная обработка (до 50 за запрос).
  https://developers.google.com/youtube/data/reference/rest/v3/subscriptions/list
- GitHub `watching` ≠ `starring`; endpoints списка watched repositories
  в 2026 изменили доступ/депрекацию. Опираться прежде всего на поддерживаемые
  stars/выбранные репозитории, не обещать импорт всех «watched».
  https://docs.github.com/en/rest/activity/watching
- Reddit и X: подтвердить доступность текущих OAuth endpoints, тариф,
  условия хранения и лимиты **перед** разработкой адаптера.
- Синхронизация «подписок» не означает право без ограничений скачивать
  приватный контент и архивировать чужие публикации.

## Экономная архитектура моделей

**Все платные задачи — только после явной активации и тестового тарифицируемого запроса**.
Отдельный диспетчер задач, не «одна дорогая модель на всё».

| Задача | Приоритетный путь | Условие принятия |
|---|---|---|
| Распознать платформу, тему, дубликат | regex/локальные правила, метаданные | бесплатно, provenance |
| Перевод короткой новости/заголовка | кеш и недорогая текстовая модель | не меняет факты, дата, язык, первоисточник |
| Перевод полного текста | локальная MT/очень дешёвый LLM по частям | explicit button, прогресс, контроль терминов и чисел |
| Пересказ YouTube | кэш → разрешённые субтитры → дешёвый LLM | никакого пересказа без расшифровки |
| Глубокое исследование и фактчекинг | более сильная модель **по запросу** | подтверждённые независимые ссылки |
| Рекомендации | существующий локальный ranker → embeddings по мере необходимости | объяснить рекомендацию, не выдумывать профиль |
| Обложки / картинки | SVG без модели → отдельная image-модель | пользователь выбрал цель, ограничение размера/цены |

**Кандидат для текстовых операций:** Gemini 2.5 Flash-Lite;
у прямого Gemini API стандартные тарифы на 22.10.2026 около
$0.10/1M входных и $0.40/1M выходных текстовых токенов.
Это лишь предварительная **гипотеза бюджета**: реальные цена, доступность,
политика хранения и модель через выбранного провайдера проверяются отдельно.
Источник: https://ai.google.dev/gemini-api/docs/pricing
Для чувствительных документов рассматривать on-prem MT при измеримой
достаточной точности, иначе явно запрашивать разрешение передачи текста.
Модель бесплатна только если соответствующий free tier реально разрешён;
не смешивать «бесплатные запросы» и «модель без ограничений».

## Перевод: UI и технический контракт

`Открыть статью` → `Сделать русский перевод` → выбор
`Кратко / Полностью`, показ оценки токенов/максимальной цены →
генерация **по желанию** → сравнение `Русский / Оригинал`,
пометка `Машинный перевод`, ссылка и время исходника.
Ключ кеша = `SHA-256(normalized source text + version of prompt + model + lang)`.
Не переписывать оригинал и не подменять verified/unverified.

Предохранители: лимит длины и токенов, очередь с одним платным заданием,
максимум $ за запрос/день/месяц, idempotency, журнал фактической стоимости
с неопределённым итогом при потере ответа. Удаление результата пользователем.
Если провайдер не настроен — показывать **точную причину**, не фиктивный перевод.

## YouTube: почему сейчас ошибка и как исправлять

В действующей версии проверяются:
`video_reports_enabled`, `openrouter_api_key`, `monid_api_key`,
`video_report_budget_enabled` и общий бюджет. Новые выжимки в UI не работают,
когда любой критический шаг не настроен. Эта итерация вводит endpoint
`/api/capabilities` только для диагностики без раскрытия ключей.
Следующий этап — безопасный бесплатный путь получения **разрешённых**
субтитров (если есть), кеш результатов, опциональное платное распознавание,
таблица фактических расходов и явный переключатель разрешений владельца.
Не утверждать, что официальный YouTube API свободно отдаёт транскрипты
произвольных чужих роликов.

## Изображения: контекст и назначение

Картинка появляется **по запросу**, а не у каждого сигнала:
`обложка к исследованию`, `схема связей`, `миниатюра Telegram`,
`инфографика по подтверждённым данным`. Для диаграмм прежде всего
детерминированная SVG/Canvas-графика; фотореалистичная генерация — отдельный
провайдер/бюджет/метаданные «AI generated». Никогда не показывать
синтетическую фотографию как документальное свидетельство события.

## План выпуска (приоритет выше календарных сроков)

**P0 — управляемость:** источник должен иметь платформу, темы, ссылку,
статус и время последнего сбора. AI-функции должны показывать причину ошибки.
Проверить HTTPS/CSRF и сборку.

**P1 — текстовое ядро:** подключить недорогой реальный переводчик с лимитами;
одна сохранённая русская статья и её первоисточник, успешный QA по цифрам.

**P1 — YouTube:** один реальный ролик → разрешённые субтитры →
краткий и глубокий русский пересказ с таймкодами → чтение в вебе,
в пределах проверенного бюджета.

**P2 — личный каталог:** создание/удаление RSS и публичных каналов
из кабинета, очереди синхронизации, частота и квоты. Сначала GitHub/RSS.

**P3 — аккаунты:** YouTube OAuth с подтверждённым read scope и кнопками
импорта/отзыва. После — Reddit и X только при разрешённом API.

**P4 — персональная разведка:** слежение за авторами/компаниями, ключевыми
событиями, раскрываемая модель ранжирования, тематические дайджесты,
граф знаний и «что изменилось».

**Граница готовности:** тесты, модель угроз для OAuth, реальный provider
response и учёт $ при платных операциях, мобильный Chromium,
отдельная проверка новых функций в Telegram, exact SHA deploy,
возможность отката. Не считать созданный PR функциональным релизом.
