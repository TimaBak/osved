# OSVED Editorial Design V1

## Назначение
Один редакционный стандарт чтения для личной ленты, статьи на сайте и Telegram. Доказательства и происхождение информации важнее длины и декоративного оформления.

## Карточка ленты
- Тематика / статус («сигнал», «проверено») / дата.
- Один ясный заголовок без кликбейта.
- Короткая суть в 2–3 предложениях, не повторяющих заголовок.
- Одна ключевая деталь при наличии, а не выдуманная «значимость».
- Кнопка прочитать, источники, прочитано, сохранить и реакции.

## Полная статья
1. Заголовок — «Что произошло», без эмоциональной оценки.
2. Главное — 2–3 коротких предложения, если есть подтверждённые факты.
3. Что известно — самостоятельные короткие абзацы или 3–5 фактов без дублирования.
4. Почему важно — только при наличии обоснованного контекста; отделять вывод от факта.
5. Ограничения / что неизвестно — по существу, без заполнителей.
6. Источники — доступные прямые ссылки и дата публикации.

Пустые разделы запрещены. Нельзя создавать факты, цифры, независимые подтверждения или перевод ради заполнения шаблона. Факты обязаны ссылаться на подтверждающие документы. Один набор данных для веба и Telegram.

## Типографика
- Комфортная ширина чтения около 65–70 символов.
- Различимая иерархия h2–h4, кегль не менее 15px в статье, строка около 1.8.
- Один тезис — один абзац. Списки только для независимых однотипных фактов.
- Выделять главное умеренно; отказаться от повторов эмодзи, ALL CAPS и маркетинговых эпитетов.
- Линки и ссылки доступны с клавиатуры и на мобильном.

## Контроль качества
- Проверить старую и новую реальную статью на desktop/mobile, светлая/тёмная тема.
- Убедиться, что небезопасный HTML не проходит мимо серверной санитизации.
- Читаемость улучшена без изменений факт-политики, статуса материала и Telegram-доставки.
- После стабилизации стилей вынести «Главное / Что известно» в отдельные семантические поля API, не распарсивать их догадками из HTML.

## Отдельный инцидент источников
Новое сообщение канала не равно событию. Для «Не баг, а фича» отдельно проверить фактическое время последнего сбора, свежие source_items, причины отклонения/дедупликации и расписание. Не смешивать эту задачу с редакционным шаблоном.
