# ОСВЕД — самостоятельное управление источниками и личные аккаунты

Дата: 2026-10-22. Приоритет: последовательная работа, не подмена API моками.

## Пять этапов до полноценного центра подписок

### 1. Навигация и самостоятельное добавление (текущий PR)
- На ПК меню прокручивается независимо; настройки доступны при любом количестве разделов.
- На телефоне шапка с логотипом и горизонтальные вкладки остаются на экране.
- В разделе источников — форма подключения **публичного YouTube-канала** по
  прямой ссылке `youtube.com/channel/UC…`. Проверка Atom-фида,
  сохранение в существующей SQLite, общий реестр для Telegram и веба,
  управление паузой, удаление без потери собранных материалов.
- URL с @именем требует предварительного разрешения ID через Monid и
  потенциально платен. Поэтому в вебе первая версия сознательно принимает
  только прямой ID. Чёткая подсказка; никаких списаний за скрытый поиск.
- Признак «канал подключён» не означает, что настройка расписания и
  автоматический выпуск новостей уже работают.
- Реальный HTTP auth+CSRF, Python-тесты, Chromium, деплой/rollback.

### 2. Универсальное управление публичными источниками
- Добавлять по URL/имени RSS, GitHub-repo, публичный Reddit, Telegram-канал,
  X-автора из одного адаптивного диалога.
- Проверять каждого провайдера отдельно, не запускать произвольные
  URL в коллекторах без SSRF-защиты и лимитов, повторно валидировать redirects.
- Настраивать категории, интересы, частоту обновления и временную паузу.
  Импорт — отдельно от активации рассылки. Не дублировать коллекторы.
- Внешние платформы могут не отдавать публичные данные бесплатно.

### 3. Личные аккаунты через официальный OAuth
- В первую очередь YouTube (свои подписки через `subscriptions.list?mine=true`)
  и GitHub; только при подтверждённых scopes и квотах.
- Затем Reddit и X по текущей доступности их API/тарифов.
- Обязательны серверное state/PKCE, шифрованное хранение refresh токенов,
  отзыв доступа, ограниченные разрешения, запись последней синхронизации,
  конфиденциальность и подтверждение импорта **перед** записью.
- Telegram user-session НЕ переносить через экспорт cookie/session-string
  в веб. Если понадобится MTProto — отдельная защищённая авторизация с
  ротацией и отзывом; сохранять текущую интеграцию бота.

### 4. YouTube и русский перевод с реальным AI
- Уже реализован ввод ссылок на видео. Он умеет находить сохранённый
  краткий конспект и выполнять существующий пайплайн Monid → OpenRouter,
  **если** сервер настроен. Не утверждать, что настройка выполнена.
- Документировать отдельно `openrouter_api_key`,
  `monid_api_key`, `video_report_budget_enabled`. Требуется
  безопасное добавление ключей в окружение Hermes, не в GitHub-код.
- Экономный порядок: cached captions → авторизованный transcript provider →
  дешёвый текстовый LLM → русский краткий пересказ или подробный разбор.
  Избегать потерь точности чисел и вымышленных таймкодов; отдельная
  прозрачная цена и лимит на запрос, кеширование.
- Машинный перевод из англ. статьи по запросу, кнопки «Оригинал/Русский»,
  отдельный cache и provenance. Без ключа — не показывать фальшивый перевод.
- На каждый платный вызов резерв бюджета, не повторять uncertain-charge.

### 5. Персональная интеллектуальная лента
- Импортированные подписки отображать по платформе, теме, автору и компании.
- Профиль интересов, явное предпочтение «больше / неинтересно / не показывать»,
  объяснимые рекомендации, режим открытий, исключения и сохранённые расследования.
- Развести персональное ранжирование и статус проверки фактов.
- Изображения: SVG-схемы бесплатно, API image generation только по
  конкретной цели (обложка/иллюстрация/инфографика) с маркировкой и бюджетом.

## Acceptance gates

Не называть «личный аккаунт подключён», если есть только URL автора.
Не называть «AI работает», если в runtime не обнаружен API ключ и не пройден
оплаченный контрольный запрос с журналом расходов.
Не называть «коллектор работает», если есть лишь запись в реестре
без реального успешного fetch. Новые функции, в отличие от планов,
подтверждать exact SHA, реальным HTTPS и браузерными сценариями.
