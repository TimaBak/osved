## 1. Текущая цель продукта

ОСВЕД — **персональная русскоязычная интеллектуальная информационно-аналитическая платформа**, а не агрегатор RSS, чат или один Telegram-бот.

Поток: **источники и аккаунты → сбор/нормализация → дедупликация → факты и происхождение → проверенное событие/карточка → русская выжимка или глубокое исследование → персональная лента и Telegram → обратная связь и память**. Сохранять различие между непроверенным сигналом и доказанной новостью. Один backend и общая SQLite для веба, Telegram и Mini App.

Продуктовые принципы:
- Подписки пользователя должны подключаться в кабинете, вручную и (при разрешении владельца) из авторизованных аккаунтов.
- Источники: платформа → конкретный канал/автор/компания/репозиторий → одна или несколько тем, возможность паузы, удаления, сбора и диагностики.
- «Источники» = управление объектами наблюдения и пакетными ссылками. «Настройки → Аккаунты» = подключить/отключить OAuth, подтвердить импорт подписок. Не смешивать публичную URL-подписку и авторизацию учётной записи.
- Нужна загрузка пакетов TXT/CSV, позднее CSV с платформой, категорией и темами; предпросмотр, дубли, выбор импорта, отчёт об ошибках.
- По возможности добавлять обычную скопированную ссылку (GitHub URL/owner/repo; Reddit r/name; YouTube @handle/URL), а не требовать технический канал ID. Для платного/ограниченного распознавания — явное согласие и лимит.
- Русский интерфейс и **действительно русские** статьи, перевод по запросу, краткие/глубокие выжимки YouTube (вплоть до PDF, таймкодов, источников), изображения по понятной задаче, бюджет и кэш. Не выдумывать перевод, субтитры или источники.
- Лента должна учиться на контексте **материала и темы**, но не автоматически «наказывать» источник/автора целиком. «Скрыть» — только убрать карточку без какого-либо предпочтения; «Прочитано» и «В избранное» тоже не равно лайку. Явные «больше/меньше» меняют профиль ограниченно; отдельные будущие сигналы для автора/компании/канала.
- Стабильные крупные категории + свои подкатегории и отдельные объекты наблюдения. Автоматическая подсказка темы с объяснением и возможностью исправить ручной выбор.
- Сайту нужны удобные боковая навигация, липкая верхняя панель, нормальные иконки, современная бело-синяя светлая / серо-синяя тёмная темы. Все основные действия — кнопки, не команды.

## 2. Что УЖЕ находится в main на момент снимка

Основано на просмотренных путях в `main`, **не на обещании готовой внешней авторизации**:

- Веб-кабинет `app/web/portal.py` и статика `app/web/portal_static/`: авторизация владельца через Telegram, CSRF, сессии, обзор, лента, радар, читатель/заметки, избранное, скрытые, настройки, источники, медиалаб и темы.
- Реестр и публичные источники `app/web/public_sources.py`, YouTube `app/video/channels.py`; добавление GitHub-repo, Reddit-community, публичных YouTube-каналов, пауза/удаление. Массовый импорт TXT/CSV упомянут в ранее слитом продуктово-функциональном релизе; проверить конкретный UI/API и ограничения по текущему коду, не утверждать поддержку произвольных RSS.
- Код **GitHub OAuth** в `app/web/github_oauth.py`, **YouTube OAuth** в `app/web/youtube_oauth.py`, защищённое хранилище токенов `app/web/oauth_vault.py`, `oauth_state.py`. В `portal.py` имеются маршруты `/api/accounts/github/*`, `/api/accounts/youtube/*`, предпросмотр/импорт YouTube-подписок, отключение GitHub и статус подключений. Успешность *реального* OAuth зависит от серверных OAuth credentials/callback/доступа API и требует отдельной проверки; проверка интерфейса с mocked API этого не доказывает.
- Codex Sale `app/llm/codexsale.py`, `model_registry.py`, `routing_policy.py`, настройки моделей `/api/ai/models`, каталог моделей `/api/ai/catalog`. Важно: часть редакционного/видео-кода и диагностика новостей всё ещё завязаны на OpenRouter; миграция маршрутов **не завершена**. В `routing_policy.py` fallback OpenRouter разрешён только opt-in.
- Хранение чтения/заметок: `app/web/reader_notes.py`; нейтральное скрытие карточек: `app/web/hidden_items.py`; ранжирование и реакции: `app/web/personalization.py`. Скрытие не меняет интересы/источник, восстановление должно быть доступно.
- Существуют коллекторы разных платформ, нормализация, редакционный/исследовательский конвейер, диаграммы и web UX. Не считать отдельный коллектор активным без реального успешного сбора.
- Telegram бот и его меню/реакции/медиалаб используют общие данные с вебом, но реальные пользовательские сценарии нужно перепроверить.
- Источники-кандидаты для следующего включения (после проверки RSS/API, ограничений, политики хранения): **Хабр, vc.ru, Tproger, OpenNET, Linux.org.ru, 4PDA, DTF**, а также **Hacker News, DEV, daily.dev, Product Hunt, Indie Hackers, Hugging Face, GitHub Trending, InfoQ, arXiv, Lobsters**. Наличие названия в плане не означает активный сбор.

## 5. Что значит готово

- *Функция есть в коде* ≠ *функция работает в аккаунте владельца*.
- GitHub `Checks success` ≠ *HTTPS smoke success*, ≠ *OAuth прошёл*, ≠ *платный AI-провайдер отвечает*, ≠ *новость доставлена*.
- Нужно фиксировать **main SHA → exact deployment SHA → live API/browser → real source fetch → saved artifacts**, без подмены тестовыми моками.
- Вносить изменения небольшими PR с анализом совместимости SQLite, безопасности OAuth, денежных лимитов, recovery/rollback.
- Перед финальным сообщением пользователю обновить handoff и явно разделить: работает, проверено только тестом, находится в плане, заблокировано внешней конфигурацией.
