# OSVED · S2 — безопасное включение источников

## Цель
Включить 8 утверждённых тематических направлений и подготовить бесплатный сбор публичных публикаций, не включая расписание, платный Monid или LLM-запросы без отдельной проверки.

## Что уже есть в коде
- `config/interests.yaml`: профиль интересов для ранжирования кандидатов.
- `app/ops/schedule.py`: циклы radar → research → delivery, включаются отдельно; при выключенном расписании фоновые расходы не создаются этим механизмом.
- `app/collectors/registry.py`: RSS/GitHub и Telegram через MTProto или Monid; X через Monid; прочие платформенные адаптеры по реестру.
- `app/collectors/ingest.py`: ограничения свежести, нормализация URL, хеш контента, сохранение в SQLite.
- `app/pipeline/selection.py`: предварительная оценка важности по актуальности, приоритету, первоисточнику, содержательности и совпадению с интересами.
- `app/radar/preference_patches.py`: предложения исправления интересов по пользовательской реакции, без скрытого применения.

## План безопасного запуска
1. Зафиксировать 24 источника как кандидатов; **не включать** их все одновременно.
2. Валидировать URL фидов и идентификаторы YouTube; отличать официальные страницы от RSS.
3. Заполнить `config/sources.yaml` (RSS/GitHub), `config/x-authors.yaml` (X), остальные источники добавлять через бот либо существующие механизмы.
4. Вначале включить 2–3 бесплатных RSS, ограничить `poll_interval_minutes`, `daily_candidate_cap` и `daily_call_cap`.
5. Проверить сохранение `source_items`, время последнего сбора, ошибки. Лишь после этого запускать исследования и доставку.
6. Для публичных Telegram-каналов предпочитать MTProto при корректной авторизации отдельной сессии; сессия содержит чувствительные полномочия, не помещать её в GitHub, логи или чат.
7. X читать через существующий Monid только после проверки стоимости и ограничений. Бесплатность Monid не предполагать. Не использовать неофициальные обходы авторизации.
8. Позже расширить режимы обнаружения: поиск по темам, похожие авторы/компании с подтверждением, объяснимые рекомендации.

## Telegram MTProto — проверки перед авторизацией
- Настройка использует `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_SESSION_PATH`.
- CLI: `osved telegram-session-setup`. Требуется интерактивная авторизация аккаунта; секретные коды, пароли и session-файлы не публиковать.
- Убедиться, что файл сессии сохраняется **в постоянном приватном каталоге**, доступном контейнеру после перезапуска, с ограниченными правами.
- `telegram_reader=true` в `doctor` говорит лишь о наличии параметров, а не о действительности авторизованной сессии.
- Не запускать чтение чужих закрытых каналов или приватных данных без разрешения.

## Кастомные Telegram-эмодзи
Набор: https://t.me/addemoji/tgiosicons. Сначала получить реальные custom emoji IDs — ссылка на набор не заменяет ID. Для InlineKeyboardButton Telegram Bot API поддерживает `icon_custom_emoji_id`, но это зависит от прав бота / Telegram Premium владельца. До проверки IDs и поддержки клиента оставить обычные символы как fallback.

## Что считать завершённым
Три публичных RSS дают записи в SQLite без расходов LLM, один публичный YouTube-канал отслеживается, MTProto-сессия проверена в отдельном тесте, UI сообщает о последней синхронизации и ошибках, расписание остаётся отключенным до решения владельца.
