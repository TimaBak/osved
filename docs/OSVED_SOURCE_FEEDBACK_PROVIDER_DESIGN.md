# ОСВЕД — продуктовые правила личной ленты и источников

Дата: 2026-10-22. Основание: обратная связь владельца, действующий код `main`,
`docs/OSVED_PRODUCT_VISION.md` и `docs/OSVED_SOURCE_ONBOARDING_PHASES.md`.
Ниже **реализованные функции отделены от следующих этапов**.

## 1. Два разных экрана

**«Источники» = кого/что читать:** выбрать платформу, добавить ссылку на канал,
сообщество, автора или репозиторий, присвоить рубрику, оценить источник, включить
или выключить сбор, импортировать пакет ссылок, увидеть последний успешный сбор.

**«Настройки → Аккаунты» = откуда у ОСВЕД есть разрешённый доступ:**
подключение личного аккаунта, согласие на чтение собственных подписок,
синхронизация, дата последнего импорта, отзыв прав и удаление токена.
Подключение OAuth не должно автоматически включать все обнаруженные каналы;
сначала предпросмотр и подтверждение импорта.

На старте не смешивать «публичный канал по ссылке» с «авторизованный аккаунт
пользователя», не хранить пароль или браузерную cookie чужой платформы.

## 2. Четыре НЕ взаимозаменяемых действия с контентом

| Действие | Что делает | Влияет ли на рекомендации? |
|---|---|---|
| Скрыть / закрыть | Убирает именно эту карточку из ленты; восстановить в «Скрытые» | **Нет** |
| Прочитано | Сохраняет отметку и заметку для библиотеки | **Нет** |
| В избранное | Сохраняет материал в библиотеке | **Нет**, пока нет явного подтверждения интереса |
| Больше/меньше подобного | Меняет индивидуальный сигнал конкретного материала и ограниченный вес **темы** | **Да** |

Скрытие **не** есть негативный интерес, снижение надёжности источника,
отписка от автора, отрицательная оценка статьи или автоматическая блокировка.
Если пользователь закрыл 20 карточек, это всё равно не значит
«тема неинтересна». Рекомендатель не читает таблицу скрытых материалов.

**Текущая реализация персонализации:** `app/web/personalization.py`,
эвристическое сопоставление темы по заголовку и краткому описанию.
Это не семантический анализ полного текста моделью. Реакция не понижает канал
целиком. Пожелание «меньше этого автора» будет отдельным явным действием.

## 3. Трёхуровневые интересы

- **Рубрики (управляемый стабильный верхний слой):** AI, разработка,
  инфраструктура, безопасность, бизнес, наука, дизайн, другие.
- **Темы (создаются владельцем):** например, AI-агенты, гипервизоры, GPU,
  стартапы, строительные технологии. Одна публикация может иметь несколько.
- **Объекты наблюдения:** компании, авторы, продукты, GitHub-репозитории.
  Можно следить или исключить именно их.

Источник может относиться к нескольким рубрикам, а публикация в нём
к другой рубрике. «Подписка» не означает «каждая статья мне нравится».
Сначала вручную выбранная рубрика и локальные правила, затем **предлагаемая**
моделью категория с объяснением и возможностью исправления.
Не перезаписывать вручную выбранную тему без согласия владельца.

## 4. Пакетное подключение без затрат

**Первая поставка:** вставка списка или файл TXT / CSV с одним URL в строке
(у CSV — первый столбец), до 25 строк, предпросмотр и выбор галочками.
В этой версии успешно классифицируются GitHub `owner/repo`, Reddit
`r/сообщество` и YouTube `/channel/UC…`. Остальные ссылки перечисляются
как неподдерживаемые и **не импортируются**. Импорт сохраняет источники
в существующем SQLite и планировщике; не запускает невидимых платных работ.

Следующий этап: стандартный CSV `platform,url,category,topics`,
создание собственных тем, дубли по canonical ID, просмотр конфликтов,
пауза массового импорта, журнал успешных и неуспешных строк.

## 5. Как упростить YouTube

Прямая ссылка `youtube.com/channel/UC…` — бесплатно и проверка Atom-фида.
`@handle`, `youtube.com/@handle`, `/c/`, `/user/` — существующий Monid
resolver при **явном одноразовом разрешении** и действующем месячном лимите.
Нет настроенного Monid или запроса подтверждения — не запускать платный вызов
и не создавать фальшивую подписку. При наличии официального API и квоты
можно позднее заменить resolver бесплатным для владельца.

## 6. Поставщики контента — кандидаты, не включённые сборщики

**Русскоязычные технологические и бизнес-источники:** Хабр, vc.ru, Tproger,
OpenNET, Linux.org.ru, 4PDA, DTF, РБК Тренды. **Внешние:** Hacker News,
DEV Community, Product Hunt, Hugging Face, Ars Technica, The Register,
InfoQ, Indie Hackers, Lobsters, arXiv.

Для каждого проверить: официальный RSS/API, разрешения на использование,
поддержку канала/автора, стабильность, язык, лицензию на хранение полного
текста, robots/ToS, rate limit, дедупликацию и статус обновления.
Ни один из перечисленных источников **не считается подключённым**
только потому, что присутствует в этом списке.

RSS с произвольным доменом — только после реализации SSRF-защиты: DNS/IP
валидация против локальных и зарезервированных адресов, повторная проверка
каждого редиректа, таймаут/размер/частота/кеш. При необходимости —
первый пилот на фиксированном allowlist.

## 7. AI-провайдер: Codex Sale прежде OpenRouter

**Авторитетный продуктовый выбор пользователя — Codex Sale.**
`docs/OSVED_PRODUCT_VISION.md` также называет его целевым.
В **PR #1** (`WIP: Codex Sale provider foundation and Telegram model settings`)
уже существуют незавершённые клиент `app/llm/codexsale.py`, каталог моделей,
назначение модели на задачу и Telegram-навигация. Нельзя считать это частью
`main` или говорить, что Codex Sale уже настроен в контейнере.

В текущем `main` видео/редактор всё ещё требуют OpenRouter, и диагностика
может ошибочно представить его отсутствие как «нет AI вообще».
Исправлять в следующем отдельном PR:
1. Изолировать и ревьюить только provider/router/model settings из WIP #1,
   не мёрджить автоматически огромную устаревшую ветку.
2. Codex Sale сделать явным основным провайдером с дешёвой моделью для
   перевода, краткой выжимки, классификации; дорогую модель — только
   для глубокого разбора по запросу. Названия/коэффициенты проверять через
   подключённый официальный `/models`, не выдавать рекламные коэффициенты за USD.
3. OpenRouter разрешить как **резервный** провайдер, а не скрытый автопереход
   при ошибке и неопределённой стоимости.
4. В настройках сайта показать подключённость, выбор модели по задачам,
   лимиты, расход и причины блокировки — без вывода ключей в браузер.
5. Проверить настоящий модельный ответ, русский результат, счёт затрат,
   обработку 402/429 и uncertain-charge. Ключи помещать только в защищённое
   окружение Hermes после явной авторизации.

## Выпускная очередь

- **V1 — этот PR:** «Скрыть/вернуть» без обучения профиля, импорт TXT/CSV,
  привычные ссылки на GitHub/Reddit и YouTube @handle с явной ценой.
- **V2:** универсальный реестр ссылок и безопасные RSS интеграции, новые
  русскоязычные площадки, проверка первого реального сбора.
- **V3:** Codex Sale / модели / деньги, русская выжимка и перевод по ссылке,
  честный runtime-status и управляемое расписание.
- **V4:** «Настройки → аккаунты», OAuth YouTube/GitHub, затем Reddit/X только
  по доступным API и отдельному согласию.
- **V5:** многоуровневые темы/авторы/компании и объяснимые семантические
  рекомендации, карта знаний, режим открытий.

Производственный статус каждой функции определяется CI, exact SHA,
успешным деплоем, браузером и доказательством реального внешнего запроса,
а не только наличием красивой формы.
